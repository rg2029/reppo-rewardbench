# Reppo RewardBench — integration smoke preview only

> **No publishable scientific results are included in this preview.** This repository is
> a data-format example to validate loading, API requests, and scoring. It is **not**
> evidence that economically coordinated feedback improves correctness, agent success,
> policy training or reinforcement learning.

## Dataset

`data/smoke_preview.jsonl` contains **10 manually checked examples derived from 5 basic arithmetic tasks**, not real coding-agent trajectories. Candidate texts include an evaluator-instruction attack for checking the API's handling of untrusted candidate content. The `claimed_correctness` labels are assertions authored with the fixture; they are not independently test-executed labels. No real model completions or peer votes are present.

## Planned scientific release

The full research track requires **100+ independently verified coding-agent tasks** and multiple model-generated candidate patches or trajectories per task. Each candidate must have an external test-run artifact, provenance of model generation, repository commit, relevant dataset rights and no train/test overlap. The sealed test split must not be used for prompt tuning. Distinct tests will compare the Reppo final composite, one independent LLM judge, uniform peer average and a genuine economic weight ablation if internal weights are provided.

## Usage

Load with `datasets.load_dataset("json", data_files="data/smoke_preview.jsonl")` or any JSONL reader. See the companion GitHub repository for a standard-library-only offline scorer and the protocol.

## Limitations and ethics

- The toy fixture **cannot establish** meaningful reward accuracy, reward hacking resistance, or RL improvement.
- API submissions may be visible on Reppo's public evaluation feed; do not submit confidential source code, hidden tests, user traces, private repos or credentials.
- Genuine coding candidates must be run only in isolated, resource-limited sandboxes.
- Claims about multiple independent judges must be conditioned on evidence of identity/model diversity; self-reported names are insufficient.
- Human researchers should examine the test oracle and the raw artifacts before citing results.

The full-system Reppo condition comprises primary evaluator swarms, secondary veREPPO-based feedback and any matching Datanet evidence. These are not separate independent public APIs.
